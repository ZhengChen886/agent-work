# 企业面试情报分析

从求职者视角出发，为目标企业+应聘岗位提供面试前深度情报分析。核心方法论是「从招聘岗位反推真实需求」——JD 里藏着企业最真实的痛点。输出可行动策略，而非泛泛的企业介绍。

## 触发条件

当用户同时提供以下两个信息时执行本技能：
1. 目标企业名称（如「深圳万物安全科技有限公司」）
2. 应聘岗位名称（如「AI应用开发工程师」）

若只给了企业未给岗位，或二者皆缺，先引导式提问补齐信息，再开始分析。

## 工作方式

- 使用 WebSearch / WebFetch 进行多轮搜索，优先权威来源（官方工商信息、企业官网、政府公告、可信招聘平台）。
- 若用 Explore 子代理并行研究，**同一时刻最多启动 3 个**，每个子代理限制 3-5 次搜索。
- 所有数据标注信息来源时间点，避免把过时信息当作当前状态。

## 执行流程

按以下五轮顺序执行。每轮先记录关键结论，再决定下一轮搜索目标，避免盲目串联搜索。

### 第一轮：企业基础画像

**目的**：确认企业性质、股权结构、组织规模、发展阶段。

搜索关键词组合：
- `"{企业全称}" 工商信息 股东 注册资本`
- `"{企业全称}" 融资 估值`
- `"{企业全称}" 员工规模 参保人数`
- `"{企业全称}" 组织架构 子公司`

| 维度 | 关注点 |
|------|--------|
| 企业性质 | 国企/民企/事业单位/法定机构/外资？是否企业化管理？ |
| 股权关系 | 母公司是谁？有没有关联公司？实际运营主体是哪个？ |
| 资金状况 | 融资轮次、金额、投资方；是否有政府背景资金？ |
| 组织规模 | 参保人数、员工总数、硕博占比 |
| 发展阶段 | 初创期/成长期/扩张期/成熟期/收缩期？ |

### 第二轮：业务全景拆解

**目的**：搞清楚企业靠什么赚钱、核心产品是什么、客户是谁。

搜索关键词组合：
- `"{企业全称}" 主营业务 产品`
- `"{企业全称}" 客户案例 合作`
- `"{企业简称}" 解决方案 行业`
- `"{企业全称}" 中标 项目`

提取信息：
- **业务线拆分**：有几条业务线？各占营收比例？哪条是现金牛？哪条是增长主力？
- **客户画像**：To B 还是 To C？政府/大企业/中小企业/个人？头部客户有哪些？
- **产品形态**：软件/硬件/服务/方案/SaaS？标准化程度如何？
- **竞争格局**：对标企业是谁？差异化优势在哪？
- **技术栈**：核心技术是什么？有没有专利/软著/资质？

阶段判断框架：

| 信号 | 判断 |
|------|------|
| 产品刚发布/仅有 Demo | 从 0 到 1 验证期 |
| 有标杆客户但规模小 | 产品市场匹配期 |
| 多岗位同时招聘、管理层岗位在招 | 快速扩张期 |
| 开始招供应链/交付/客服岗 | 从研发转向量产交付 |
| 招聘频率下降、开始优化 | 收缩调整期 |

### 第三轮：招聘岗位精准拆解

**目的**：找到目标岗位及同批次招聘的其他岗位，反推真实招人目的。

搜索关键词组合：
- `"{企业全称}" "{目标岗位}" 招聘`
- `"{企业简称}" 招聘 {城市名}`
- `"{企业全称}" 社招 校招`
- `site:zhipin.com "{企业简称}"`
- `site:lagou.com "{企业简称}"`

提取信息：
- **目标岗位 JD 细节**：职责描述、技术要求、经验要求、薪资范围
- **同批次其他岗位**：同时还在招什么岗？组合起来指向什么业务动作？
- **岗位层级**：执行层（初级/实习）还是决策层（负责人/总监）？
- **经验要求信号**：3-5 年=需要能独立干活；8 年+=需要能带团队；接受应届=培养储备

招人目的反推逻辑：

| 招聘组合信号 | 真实目的判断 |
|-------------|-------------|
| 销售+区域经理同时招 | 拓新区域市场 |
| 技术岗+硬件经理同时招 | 技术团队从草台班子走向正规化 |
| 采购+供应链岗在招 | 从自研转向量产，需要搭建供应链 |
| 测试/QA 岗在招 | 产品走向规范化质量管控 |
| 管理岗在招但执行层不在招 | 可能是替补流失的管理者 |
| 大量初级岗+实习生 | 低成本扩张，可能有裁员风险 |

### 第四轮：招人时机与背景验证

**目的**：确认招人的时间窗口和外部触发因素。

搜索关键词组合：
- `"{企业全称}" 最新动态 新闻`
- `"{企业简称}" 发布 上线 合作`
- `"{企业全称}" 战略 规划 目标`

验证点：
- 近期是否有融资到账？→ 资金到位触发扩张
- 近期是否有新产品/新平台发布？→ 产品上线需要配套团队
- 近期是否有重大合作/中标？→ 业务增量需要人手
- 近期是否有行业政策变化？→ 政策红利触发新业务线

### 第五轮：面试策略制定

基于前四轮信息，输出三部分：

#### (1) 面试验证问题清单
分三类设计问题，帮用户在面试中反向套出真实信息：
- **验证业务判断的问题**（2-3 个）：验证对公司业务、产品、客户的理解是否准确
- **挖招人真实目的的问题**（2-3 个）：锁定进去后要解决什么问题
- **判断工作体验的问题**（2-3 个）：了解团队氛围、汇报关系、考核方式

#### (2) 能力匹配建议
按岗位类型给出应突出的能力和经验：
- 技术岗：突出的技术栈和项目经验
- 销售岗：突出的行业资源和成单案例
- 中后台岗：突出的管理和协调能力

#### (3) 风险提醒
基于企业性质和发展阶段，提示隐性风险：
- 体制内/事业单位：决策流程、薪资天花板、技术话语权
- 初创公司：资金链、职责边界模糊、加班强度
- 快速扩张期：管理混乱、流程不健全、一人多岗

## 输出格式

最终输出按以下结构组织：

### 1. 企业定性（一段话）
一句话概括这是什么性质的企业、当前处于什么发展阶段。

### 2. 业务全景拆解
- 核心业务线及营收结构
- 客户画像
- 产品形态与技术栈
- 竞争格局

### 3. 招聘岗位反推分析
- 目标岗位 JD 关键信息提取
- 同批次招聘组合分析
- 招人真实目的判断（核心结论）

### 4. 招人时机判断
- 近期触发招人的外部事件
- 企业当前所处阶段

### 5. 面试策略
- 面试验证问题清单
- 能力匹配建议
- 风险提醒

## 注意事项

1. **区分企业性质**：国企/事业单位/民企/外资分析逻辑完全不同，不套用同一套框架。
2. **关注实际运营主体**：注册地与运营地、母子公司关系，搞清面试的到底是哪个实体。
3. **不要只看目标岗位**：同批次其他岗位往往暴露更真实的业务意图。
4. **薪资信息要谨慎**：搜不到准确薪资时给出合理区间并标注为估算。
5. **时效性标注**：所有数据标注信息时间节点。
6. **招聘信息不存在时**：搜不到目标岗位公开招聘信息时明确告知用户，基于企业整体招聘动态做推断性分析并标注为推断而非确认。
